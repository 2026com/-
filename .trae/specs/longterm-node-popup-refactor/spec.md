# 长期目标节点弹窗重构规格说明书

> 自然语言：中文
> 创建时间：2026-08-14
> 版本：v1.0

---

## 一、问题陈述

**现状问题**：
1. `NodePopup.jsx` 有 3 个标签页：`执行`(actions)/`方案`(plan)/`配置`(config)。**执行标签页提供启动番茄钟 🍅、手动秒表 ⏱ 两套计时功能**，与「阶段 2 日常打卡页面统一计时」定位重复冗余，入口分散导致用户流程不聚焦。
2. 新建节点（画布双击 / 弹窗内「新增子任务节点」按钮）直接以固定默认名 `新目标`/`子任务` 创建**无命名节点**，画布上出现大量无名空白节点，画布可读性极差。
3. `配置` 标签页强制绑定「📁 七大系统归类」选框 + 自动/手动双权重进度配置 + 四色状态切 12 项，功能过载、非核心，用户在弹窗前需要滚动浏览才能找到要改的项。
4. 父子级结构与方案文本割裂：当前「AI写执行方案」仅写入 `node.executionPlan` 长文本，**没有生成真实的子节点**，父子级结构仍然需要手动逐个点击创建，流程割裂、落地性差。
5. 生成的 AI 内容在每次刷新页面 / 升级版本后不被保留为独立节点（仅在 textarea 文本里），导致子层级任务连贯性被打断，用户修改过的步骤可能被下一次「AI 写执行方案」覆盖。

---

## 二、目标用户 & 目标

### 目标用户
- 小美 App 的重度使用者：在「长期目标思维导图」页规划大目标（如练习钢琴 / 学习网络安全），希望 AI 帮拆解到可落地执行的子步骤，然后一键把可落地的原子步骤下发到「日常打卡」做真正的日循环打卡与计时。

### 产品目标（Goals）
| # | 目标 |
|---|---|
| G1 | 入口单一化：**所有计时 / 打卡交互统一收口到阶段 2 日常打卡页面**，长期目标节点弹窗不再内置任何计时控件，完全聚焦「方案拆解 + 下发」 |
| G2 | 数据一致性：新建节点**必须强制命名**，杜绝匿名空白节点；AI 生成内容落地为真实子节点（不是仅写文本），刷新页面 / 版本升级不丢失，用户手动增删改的结构不会被二次 AI 生成覆盖（AI 只负责初始产出） |
| G3 | 轻量聚焦：弹窗默认 2 标签「方案 / 配置」，配置项仅保留 2 个；默认紧凑 + 展开大编辑双形态，简约大留白无冗余组件 |
| G4 | 可落地：AI 生成后，用户可以勾选任意**子级（叶子）节点**一键推送下发到日常打卡 → 生成打卡卡片，后续在日常打卡页真正做打卡 + 番茄计时 |

### 非目标（Non-Goals，明确不做）
- NG1：不在本弹窗内实现真实番茄钟计时 UI（倒计时进度环 / 开始暂停按钮 / 完成音效等）— 全部交给 DailyHabitsPage。
- NG2：不引入 HTML5 拖拽 API（dnd-kit / react-dnd）进行父子级树的复杂重排；本版用**「升级为父级 / 降级为子级」显式按钮**实现层级调整 + 现有画布拖拽即已天然支持节点位置移动，**不新增新的拖拽框架依赖**。
- NG3：不调真实 LLM API。AI 生成逻辑走纯前端关键词匹配模板（复用现有 `aiLogic.js` 思路，新增分粒度的生成函数即可）。
- NG4：不删除、不重写现有思维导图画布的贝塞尔连线 / 自动布局算法，只动弹窗相关交互。
- NG5：不强制要求所有下发的习惯与节点绑定双向同步（即：下发后日常打卡删了习惯不会反向删除节点，节点改名也不会自动改已下发的习惯名，保持两边独立，避免逻辑循环依赖）。

## 三、功能需求（Functional Requirements）

### FR1：弹窗瘦身 —— 彻底移除【执行】标签页
- 规则：弹窗 Tabs 区域仅保留 2 项，顺序为：`📋 方案`（默认激活选中）、`⚙️ 配置`
- 规则：删除代码中以下按钮与相关调用链：
  1. `startPomodoro()` 启动番茄钟函数 + 🍅按钮
  2. 「手动秒表 ⏱」按钮 + ADD_TIMER_RECORD 调用
  3. `renderTab('actions', '执行', '🎯')` 入口
- Rubric：执行相关代码 100% 从 NodePopup.jsx 移除，Grep `startPomodoro\|pomodoro\|stopwatch\|ADD_TIMER_RECORD.*nodeId` 不得再命中 NodePopup.jsx（允许 AppContext 保留 action 类型供 DailyHabitsPage 用）

### FR2：新建节点强制命名 —— 杜绝匿名空白节点
场景分两类，都要拦截：
- 规则 FR2.1：画布空白双击新增根节点（MindMapCanvas.jsx `onCanvasDblClick`）：
  1. 不立即 dispatch ADD_NODE；
  2. 先通过 ModalRoot prompt 输入框：title=「请输入长期目标名称」，placeholder=「例：学习钢琴 / 备考雅思 / 健身减脂」，默认值空；
  3. 用户点击取消 / 输入字符串 trim 后为空 → **完全取消创建**，不产生任何节点写 localStorage；
  4. 用户点击确认且有合法名字 → ADD_NODE，title=合法名字，其他默认字段和原先一致。
- 规则 FR2.2：NodePopup 内「➕ 新增子任务节点」按钮：
  1. 不立即 dispatch ADD_NODE；
  2. 先弹 ModalRoot prompt，title=「请输入子任务名称」，placeholder=「例：练习C大调音阶」；
  3. 取消 / 空 → 不创建；否则创建，parentId=当前 nodeId。
- Rubric：所有 `ADD_NODE` 的 payload.title 字段，要么来自 prompt 输入（用户输入非空值），要么来自 AI 生成（见 FR4，也是非空字符串）；代码里 Grep 不得再出现 `title: '新目标'` 或 `title: '子任务'` 硬编码默认名。

### FR3：【配置】标签页裁剪 —— 仅保留 2 项核心设置
配置页 UI 规则（从上到下依次渲染）：
1. **🗓 目标截止日期**：`<input type="date">`，绑 `node.dueDate`（新增字段，类型 string yyyy-mm-dd 或空）；
2. **⚖️ 目标权重**：数字输入框 min=0 max=100，默认 20，绑 `node.weight`；
3. 保留右下角独立「🗑 删除」大按钮（见 FR6）。
- 规则 FR3.1：删除以下全部配置项（注意是**彻底删除**，非隐藏）：
  - 🟢🔵🟠🔴 四色状态切换按钮组
  - 📁 七大系统归类（SEVEN_SYSTEMS map 按钮 7 个）
  - 🎯 任务进度 range 滑块 + 父级进度说明
  - 整个「⚖️ 双权重配置（自动/手动切换）」段 + 切换按钮 + 子节点权重表格
- 规则 FR3.2：删除 `import { NODE_STATUS, SEVEN_SYSTEMS } from '../../utils/constants.js'` 里 NODE_STATUS、SEVEN_SYSTEMS 的未使用引用（如不再使用则移除）。
- Rubric：配置页所有字段渲染完成后，整体高度 ≤ 180px（紧凑预览下），无滚动条。

### FR4：父子级 AI 生成逻辑 —— 两档颗粒度
新增两组 AI 生成函数（前端模板模拟，不请求外部 API）：

- 规则 FR4.1 —— **父级节点 AI（宏观层级框架）**：当当前被点击的节点为父级节点判断条件（level=0 或 children.length=0 但被判断为"大目标"）或用户明确在父节点上点按钮 → 输出**树状层级框架，不生成过细单次动作**：
  - 输出数量：3~5 个**中间分支子节点**（例：练习钢琴 → `基础乐理` / `手指基本功` / `曲目练习` / `舞台实践`）
  - 每个子节点只含 title + level+1，不含 description（因为这些子节点用户再次点击后还能再自己调 AI 生成更细）
  - 写入方式：**真实 ADD_NODE 3~5 次，parentId=当前父节点**，这样下次打开父子级关系直接就在思维导图画布上渲染
- 规则 FR4.2 —— **子级节点 AI（细颗粒原子动作）**：当节点 parentId!=null（一定不是 0 级根节点）→ 输出**马上就能动手做的具体行动步骤**，要求：
  - 每条步骤必须包含**明确动词 + 具体数量 / 时间**（例：✓ 观看「钢琴入门教学 No.3」15 分钟视频 ✓ 分手慢练 C 大调音阶 2 遍，每遍 60 BPM ✓ 练习《小星星》片段 8 小节）
  - 输出数量：4~6 个子节点，真实写入 parentId=当前子节点（变成当前子节点的 children，形成 3 层树：根→中间分支→原子动作）
- 规则 FR4.3 —— **幂等保护（防覆盖用户修改）**：
  - 点击「AI写执行方案」时，先检查：`state.nodes.filter(n => n.parentId === nodeId).length > 0`？
  - 若 > 0（该节点已经有任何孩子，无论 AI 还是用户手动创建的），弹出 ModalRoot confirm：「当前节点已存在 ${n} 个子步骤，AI 生成会**追加在现有子节点后面**（不会覆盖 / 删除已有），是否继续？」；用户同意才继续，不同意则退出
  - 若 === 0（无子节点）：直接生成，不需要 confirm
  - 生成方式：**追加式写入**，绝不 UPDATE_NODE / DELETE_NODE 已有子节点 —— 保证"AI 生成内容以及方案只能由使用者调整或者删除"的约束
- 规则 FR4.4：AI 生成后，自动把 popup 当前 tab 保持在 plan，并且方案树渲染区域自动刷新（因为 state.nodes 已变，React 重渲染即可，无需额外操作）。
- Rubric：父级生成模板 ≥ 8 个不同匹配键（钢琴、编程、健身、语言、考试、摄影、写作、通用）覆盖率 ≥ 80% 常见标题；子级生成每个步骤必须满足正则：`/(\d+\s*(分钟|遍|次|小时|小节|页))|(观看.*视频)|(阅读.*章)|(完成.*练习)/` 每条都有明确可执行度量单位 / 动词。

### FR5：【方案】标签 —— 树状结构自由编辑
方案标签内渲染树状思维导图列表（不是画布，是轻量列表视图），提供显式层级操作按钮，**不引入新的拖拽库**：

- 规则 FR5.1 —— 视图结构：
  - 顶部两按钮（左 / 右排列）：
    - 左侧「✍️ AI写执行方案」（主按钮，靛青底）
    - 右侧「➕ 新增子任务节点」（次按钮，绿底）
  - 中间区域：树状列表，渲染该节点的**所有直接 + 后代节点**（递归渲染）
  - 每一条行卡片包含：
    - 缩进：按 level × 16px 左边距（直观体现层级）
    - 标题 input：可直接编辑节点标题，onBlur / onChange 立即 UPDATE_NODE 写 localStorage
    - 右对齐操作区（4 个图标按钮）：
      1. ⤴️ 升级为父级：把该节点的 `parentId` 改为它**父节点的 parentId**（即向上跳一级）；若当前父节点已经是根节点（parentId==null），则把该节点升级为独立根节点（parentId=null），x/y 给默认空让自动布局算
      2. ⤵️ 降级为子级：弹窗让用户选择**同级的任一兄弟节点**作为新父节点（选择器 radio 列表）；选中后 parentId=该兄弟节点 id
      3. 📤 推送至日常打卡（仅**叶子节点**显示：即 state.nodes 查无后代 children 的才显示）
      4. 🗑 删除节点：本节点级删除（二次确认，仅删自己 + 它的后代，避免误删）
    - 叶子节点特殊视觉：左边距有一个额外的 🍃 图标标识
- 规则 FR5.2 —— 📤 推送至日常打卡（核心联动）：
  - 仅对叶子节点可见（避免把父级宏观分支直接下发到日常）
  - 点击弹出 ModalRoot confirm：`将「${node.title}」推送到日常打卡视图，生成打卡卡片？`
  - 用户确认：dispatch `ADD_HABIT`，字段映射：
    ```js
    habit.title = node.title
    habit.reminderTime = node.reminderTime || '09:00'  // 默认9点，可下发后用户在日常页改
    habit.duration = 25                                  // 默认25分钟
    habit.difficulty = 'medium'                          // 默认中等
    habit.sourceNodeId = node.id                         // 关联字段，标记来源（可后续扩展，当前仅用于追溯）
    ```
  - 成功后 toast：`✅ 已下发「${title}」到日常打卡（共 X 项 / 习惯数 ≤ 12 会被拒绝并提示"日常打卡已达12项上限，清出空位再推送"）`
  - 若 habits.length ≥ 12，ModalRoot alert 拦截，不下发，不写 localStorage
- Rubric：推送下发逻辑单测 / 手动验证：1 叶子节点下发后，日常页 `state.habits` 长度 +1 且 sourceNodeId 正确；≥12 项时长度不变；父级节点行「📤」按钮渲染为 disabled + 灰色 opacity-40。

### FR6：弹窗两种视图 + 删除按钮布局
- 规则 FR6.1：弹窗尺寸两档切换
  - 默认紧凑模式：`w-96 (384px)` 宽（比原 w-80 稍宽，容纳方案树缩进），`max-h-[70vh]`
  - 头部最右上角 `×` 关闭按钮左边增加一个展开切换按钮：「⬜ 展开 / 🗗 收起」图标按钮
  - 展开模式：居中 `fixed inset-0 m-auto`（即不是挂在节点旁边，变成屏幕中央大屏），尺寸 `w-[80vw] h-[80vh] max-w-5xl max-h-[900px]`，方案区域 `max-h-[calc(80vh-180px)] overflow-y-auto` 显示大编辑界面
- 规则 FR6.2：点击弹窗外部关闭
  - 弹窗 DOM 外围包一层 overlay（透明全屏 mask，z-index 39，比弹窗 40 低），点击 mask 触发 onClose
  - 紧凑模式（节点旁小窗）时，弹窗本身挂在 NodePopup 的 getPosition() 计算坐标，overlay 仍然全屏覆盖，点击节点旁以外任何地方（含 mask）关窗
- 规则 FR6.3：右下角独立删除按钮
  - 删除按钮固定在弹窗右下角 **24px × 24px 间距隔离带内**，和其他所有操作按钮区视觉上独立分隔，不与【新增 / AI 写方案 / 保存】等主操作挨在一起
  - 按钮为：`p-3 rounded-xl bg-rose-50 text-rose-600 text-sm font-semibold hover:bg-rose-100`（大按钮，含文字「🗑 删除节点」）
  - 点击弹出二次 confirm：文案「⚠️ 确认删除节点 「${title}」？删除后会一并移除它的 ${N} 个子步骤，**且无法恢复**。」；确认后 DELETE_NODE + onClose；取消不动作
- Rubric：展开模式下弹窗居中 + 不超出视口边界（max-w/max-h 生效）；删除按钮四周留白在 4 个方向都 ≥ 16px，无任何相邻触碰。

### FR7：数据持久化 & 稳定约束
- 规则 FR7.1：升级 DATA_VERSION：为了让所有用户打开后**自动清空旧 mockData 里的钢琴 / 网安预置节点（按用户要求「不预置示例任务」）**，`constants.js` DATA_VERSION 升级为 `1.0.4-20260814-tree-ai-popup`，保证 initMockData 不再注入旧示例
- 规则 FR7.2：新增字段定义（向后兼容，老 localStorage 没有这些字段则用默认值，读取不会崩）
  - `node.dueDate: string?` —— 配置页截止日期 yyyy-mm-dd
  - `node.reminderTime: string?` —— 提示时间（下发到日常 habit 默认值时用）
  - `habit.sourceNodeId: string?` —— 来源节点 id 追溯
- 规则 FR7.3：AI 生成仅首次追加，不自动重跑
  - 用户每次打开弹窗 → **绝不自动调 AI 函数**
  - 只有用户**手动点击**「✍️ AI写执行方案」按钮才执行生成
  - 且 FR4.3 的幂等保护要求确保：已有节点绝不覆盖，仅追加
  - 用户手动增删 / 修改标题 / 调整父子级 → UPDATE_NODE / DELETE_NODE 直接写 localStorage → 刷新页面 100% 保留

## 四、非功能需求（Non-Functional Requirements）

| 编号 | 分类 | 要求 |
|---|---|---|
| NFR1 | 性能 | 打开弹窗 ≤ 200ms；AI 生成 5 个节点 ≤ 20ms（因为纯前端模板生成） |
| NFR2 | 兼容性 | localStorage 老用户升级不会崩：新字段 dueDate / reminderTime / sourceNodeId 读取不到时必须有默认值 |
| NFR3 | 依赖 | 严格零新增 npm 依赖；不引入 dnd-kit / react-dnd / any LLM SDK；aiLogic.js 内纯逻辑 |
| NFR4 | 可访问性 | 所有按钮必须有 aria-label（⬜ 展开、× 关闭等）；输入框有 label；键盘 Tab 顺序正常 |
| NFR5 | 代码风格 | 所有 JSX 保持项目现有风格：Tailwind 原子类、圆角 rounded-xl / rounded-lg、border-slate-200 细边框、不写行内 style 除了背景色 |
| NFR6 | 一致性 | 配色、留白、圆角与 DailyHabitsPage 弹窗完全一致（bg-white/50，border-slate-200，touch-feedback 类保留） |

## 五、约束、依赖、假设 & 开放问题

### 约束（Constraints，硬红线）
- C1：禁止新增第三方 npm 依赖
- C2：禁止在长期目标节点弹窗内有任何计时 UI（倒计时 / 番茄钟进度 / 暂停继续按钮） —— 全在 DailyHabitsPage
- C3：新建节点（双击画布 / 新增子节点按钮）→ 必须 prompt，禁止空名 / 默认名创建
- C4：AI 生成内容必须落地为真实 nodes（不是仅写 executionPlan 文本），必须 localStorage 持久化

### 依赖（Dependencies）
- D1：复用现有 `ModalRoot.confirm / prompt / toast / alert` —— payload 不能有 ReactNode，只能传纯 JS 字符串（已在本约束中遵守，所有 modal payload 都用字符串文案）
- D2：复用现有 reducer `ADD_NODE / UPDATE_NODE / DELETE_NODE / ADD_HABIT` —— 已有且全部 localStorage 双写，无需新增 action
- D3：复用现有 `utils/storage.js` 的 `uid()` 函数生成 nodeId / habitId

### 假设（Assumptions）
- A1：用户下发习惯到日常打卡后，不会反向同步，两边独立 —— 用户如果删节点不会删习惯，改节点标题不会自动改已下发的习惯
- A2：AI 生成本地模板覆盖率 80% 即可（用户可手动补全），不需要覆盖所有可能的目标标题
- A3：不接真实 LLM —— 用户知道这个 AI 是内置规则模板生成

### 开放问题（Open Questions，无 / 用户已通过需求明确给了答案）
- 本规格说明书不存在未决开放问题，所有功能点用户在 3 轮需求迭代中已明确给出答案。

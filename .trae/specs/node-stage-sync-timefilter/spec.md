## 2. 功能需求（Functional Requirements）

### 2.1 节点状态 & 进度条（对应需求 1 ①②）

- FR-1.1 `NODE_STATUS` **扩展为 5 态**：
  - `todo` 待开始（蓝）；`progress` 进行中（青）；`paused` 暂停（橙）；`done` 已完成（绿）；`aborted` 放弃搁置（红）。
  - 每一个节点必须自带**状态徽标**（节点左上角彩色圆角胶囊 + 2字缩写：待开/进行/暂停/已完/放弃），禁止把状态图例统一放在幕布底部（删除原左下角四色状态栏）。
- FR-1.2 节点**正下方**恢复小型进度条 + 百分比数字：
  - 进度条宽度 = 节点宽度 × 0.9；
  - 显示百分比取整数（0~100）；
  - 若节点为 `aborted / paused → done态 / 进度100 时颜色仍绿色`：进度颜色和状态颜色独立。
- FR-1.3 **搁置/放弃的子节点不计入父进度统计**：
  - `recalcParentProgress` 内传给 `calcProgress` 的 children 需先过滤 `status === 'aborted' || status === 'paused'`（搁置 & 放弃都从分子分母剔除，等价于"停更任务不影响主干进度"）。

### 2.2 下发按钮回归 & 双向同步（对应需求 3 ①②）

- FR-2.1 `NodePopup` 顶部增加一个**显性主按钮**：「📤 下发（复制）到日常打卡」，点击逻辑：
  - 若当前节点是叶子：把"自己"下发，payload 保留 `sourceNodeId = node.id`；
  - 若当前节点是非叶子：把"全部叶子后代"批量下发（≥1 条命中上限/已存在判断）；
  - 若 habit 已经存在同 sourceNodeId 的条目：toast 提示「⚠️ 该节点已经下发过」，跳过重复。
- FR-2.2 双向同步：在 `reducer TOGGLE_CHECKIN` 中检测 habit 的 `sourceNodeId`：
  - 打卡勾选（value=on）→ 对应 node 的 `status='done'`, `progress=100`；
  - 打卡取消勾选 → 对应 node 的 `status='todo'`, `progress=0`；
  - 改动后立即调用 `recalcParentProgress` 向上回溯，父级进度/节点下方进度条立刻更新。

### 2.3 移除自定义标签（对应需求 2）

- FR-2.3 全项目检索 `tag / labels / 自定义标签 / tagModal` 等相关入口（UI 菜单 / 弹窗 tab / reducer action），全部置为"死代码或移除"，保证用户不可触达。若 NodePopup / 配置页原本有 tab，保持 2 标签（方案/配置）不扩第三。

### 2.4 幕布右上角控件（对应需求 4 ①②）

- FR-2.4 在 `LongTermGoalsPage` **右上角**新增一个控件栏（与右下角工具栏对称位置）：
  - 控件 1：三档时间筛选 pill — `本周 / 本月 / 全部时间`（默认"全部"）。
    - 判定规则：对根节点集合按 `deadline` / `dueDate` 或 `createdAt + estimatedHours` 推导时间窗，仅当"节点整个时间带与筛选窗口相交"才保留渲染（连线也仅保留两端都渲染的对）。
    - `本周`：今天所在周一 0 点 ~ 周日 24 点；`本月`：1 号 ~ 月末；`全部`：不过滤。
  - 控件 2：**预估完成时间**显示：
    - 计算范围：当前筛选集合内所有未完成（非 done/非 aborted）叶子的 `estimatedHours` 汇总 → 按"日均工作 4 小时（内置常量，本期不暴露配置）"换算"预计剩余天数"，再叠加今天得出预计完成日期：
      - 文案：`⏱ 预计完成：YYYY/M/D（剩 N 天 · 合计 H 小时）`；
      - 无未完成任务：显示 `🎉 全部任务已收尾！`。

### 2.5 支持多并行长周期任务（对应需求 5）

- FR-2.6 多根节点不重叠：当前 `ROOT_GAP_Y=220` 固定，需改为**按每个根节点的子树高度**动态分配根起始 y：
  - 定义 `calcTreeHeight(rootId)`：把 root 的全部后代 `y 最大 - y 最小 + NODE_H` 当作树高；
  - `root[i].y = PIANO_ROOT_Y + Σ(root[0..i-1] tree height) + Σ(root[0..i-1] TREE_GAP)`，其中 `TREE_GAP = 80`（根之间空隙，比 ROOT_GAP_Y 紧凑但保证不遮挡）。
- FR-2.7 连线层 `NodeLinks` 仅过滤两端都 `visible=true` 的父子对，避免过滤后的半连线飘空。

### 2.6 节点视觉改造 → 对标「笛子学习路线图」风格（补充用户截图诉求）

- FR-2.8 **一条中心横线**（原顶部时间轴保留，同时新增一条贯穿"中心节点"的加粗主路径线——把所有处于 level=0 和 level=1 的中心串联节点用宽度为 4 的深色贝塞尔主路径连接，视觉上就是学习路线）。
- FR-2.9 **节点视觉升级**：
  - level=0/1（"阶段节点"）改为大号 **ellipse 椭圆**，内有 **序号 1/2/3/4/5/6** 左上角圆形徽章 + 标题居中文本；
  - level≥2（"知识点卡片"）改为参考图下方的白底圆角卡片，上边框对应状态色，标题占 2 行；
  - **初期/中期/后期三阶段垂直分隔带**：把 165 天时间轴按 `0~33% / 33%~66% / 66%~100%` 分成三段：`前期·建立基础 / 中期·进阶攻坚 / 后期·表演巩固`，每段上方文字大标题 + 下方浅色半透明垂直背景（贯穿整个画布高度），不同段的节点根据其 deadline 落在哪个段内自动变色（但内容不变）。
- FR-2.10 参考图底部学习逻辑黑条（先会吹 → 再吹响 …）本期不做，保持"非目标"不扩。

## 3. 非功能需求（NFR）

- **NFR-1（存储兼容）**：DATA_VERSION 升级触发清缓存，但**不主动清空用户已录入的 habits/checkins**（仅清 nodes 后重新按升级字段补默认值；用户老数据迁移逻辑可保留）。
- **NFR-2（性能）**：300 节点以内，画布拖拽 / 筛选切换响应 ≤ 100ms；不得出现全屏 re-render 抖动（useMemo/useCallback 必须覆盖 `visibleNodes` 计算）。
- **NFR-3（可回退）**：新增筛选 / 阶段分隔均不写入 `storage`，纯 UI 状态（local useState），避免污染持久化。
- **NFR-4（兼容性）**：所有操作路径在桌面浏览器 + TRAE 内置预览 Chrome 内核 ≥ 110 正常显示，不依赖 WASM/实验特性。
- **NFR-5（代码边界）**：AI 配置 / 侧边 7 系统 / 打卡数据结构不改变字段名，老 UI 依旧工作。

## 4. 验收标准（Acceptance Criteria）

> 类型：`rule` = 可客观验证的二值条件；`rubric` = 主观打分 + 阈值

| 编号 | 类型 | 验收标准 |
|---|---|---|
| AC-1 | rule | NODE_STATUS 存在且 key 列表为 `todo/progress/paused/done/aborted`，label 对应中文 5 态。 |
| AC-2 | rule | MindNode 组件渲染输出包含节点左上角"状态徽标"（DOM 可见，非 tooltip）；左下角原 4 色图例在 `LongTermGoalsPage` 中不再渲染。 |
| AC-3 | rule | MindNode 节点正下方进度条 + 百分比 DOM 渲染且宽度 = 节点宽度 × 0.9（可通过 DOM 测量）。 |
| AC-4 | rule | 当一个父节点下面有 3 个子节点，其中 1 个 `aborted` + 1 个 `paused` + 1 个 `done`，父节点进度应 = 100%（仅 done 那条计入）。 |
| AC-5 | rule | `NodePopup` 顶部有一个 `📤 下发（复制）到日常打卡`的主按钮（非行内图标）。 |
| AC-6 | rule | 对一个 `sourceNodeId` 对应的习惯打卡 → 幕布节点 `status=done & progress=100 & 父级进度立刻改变`；取消打卡 → 回到 todo/0（浏览器 DevTools 查看 state.nodes）。 |
| AC-7 | rule | `LongTermGoalsPage` 右上角存在一个控件栏，包含三个时间筛选按钮（本周/本月/全部时间）+ 一行预估完成时间文字。 |
| AC-8 | rule | 切换"本周"后，筛选窗口外的根节点不渲染（DOM 节点个数观察）。 |
| AC-9 | rule | 创建 2 个根节点（钢琴 1-6 月 & 网安 1-6 月），每个根下 40 个子节点；渲染后 2 个根的**子树包围盒 y 区间不相交**（不重叠）。 |
| AC-10 | rule | `初期/中期/后期`3 段垂直分隔带在画布上宽度相同，顶部大标题文字可肉眼可读。 |
| AC-11 | rule | 全项目 UI 入口中不存在"自定义标签 / 标签管理 / AddTag"字样（grep + 手动核对）。 |
| AC-12 | rubric | **节点视觉相似度（0-5）**：和参考笛子路线图在"中心大横线 + 阶段椭圆带序号 + 下方知识点卡片 + 垂直三段分割"这 4 条维度吻合度；**阈值 ≥ 4**（满分 5）。 |
| AC-13 | rubric | **大任务并行布局（0-5）**：多任务不重叠 + 子级连线不交错；**阈值 ≥ 4**。 |
| AC-14 | rubric | **双向同步直观性（0-5）**：打卡→幕布联动即时且可撤回；**阈值 ≥ 4**。 |

## 5. 约束 / 依赖 / 假设 / 开放问题

- **约束 C1**：不得改动 `storage.js` 中 `STORAGE_KEYS` 字段名（老用户浏览器已有数据）。新增字段走 `node.phaseHint` 或 settings 可选字段，默认空即可。
- **约束 C2**：不引入新依赖（例如日期库 dayjs），继续用原生 Date。
- **依赖 D1**：本项目已经存在的 `MindMapCanvas.jsx` / `MindNode.jsx` / `NodePopup.jsx` / `LeftDrawer.jsx` / 侧边导航重构代码必须保留。
- **假设 A1**：用户说"发送的截图"指附在本轮消息里的笛子学习路线黑白图（在本次 Spec 里按文字特征还原即可）。
- **OQ-1（不阻塞实现，按设计稿默认）**：三阶段时间带比例 33/33/33 是否改为按真实根节点 deadline 平均？→ 默认按 165 天 × 33%。
- **OQ-2**："预估完成时间"换算 `日均4h` 是否暴露？→ 本期内置常量不开放 UI。
